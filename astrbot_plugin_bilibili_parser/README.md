# Bilibili 视频解析、动态与直播订阅 · v0.5.2

适用于 AstrBot + OneBot v11 / NapCat。在开启的 QQ 群中收到 Bilibili 链接或分享卡片后，先发送磨砂玻璃信息卡，再发送 MP4 视频。

新增 UP 主动态订阅：支持 QQ 指令和 AstrBot 原生 Web 页面管理，两个入口共用 SQLite 数据库。支持视频、文字、图文、转发、专栏和其他公开动态。这里的“订阅”只记录 UID，不修改你的 Bilibili 关注列表。

## 安装

本项目代码按 [GPL-3.0-only](LICENSE) 发布。贡献说明见 [CONTRIBUTING.md](CONTRIBUTING.md)，安全问题反馈见 [SECURITY.md](SECURITY.md)。公开仓库前，请按 [OPEN_SOURCE_CHECKLIST.md](OPEN_SOURCE_CHECKLIST.md) 核对图片素材授权和本机数据。

1. AstrBot 版本要求 `>=4.24.1,<5`，动态 Web 页面使用 AstrBot 原生 Pages/API；插件会自动适配旧版 Quart 和新版 FastAPI Web 后端。已在 Windows、AstrBot 4.28.1 的 UV 环境验证。先连接 NapCat 的 OneBot v11。
2. 在 **运行 AstrBot 的环境**中安装 FFmpeg，并保证 `ffmpeg -version` 可执行。
3. 打开 AstrBot WebUI → 插件管理 → 从文件安装，上传 `astrbot_plugin_bilibili_parser-v0.5.2.zip`。依赖由 AstrBot 按 `requirements.txt` 安装。
4. 打开插件配置，设置群过滤模式和群号，保存。**默认是空白名单，安装后不会自动回复所有群。**

如果自动安装依赖失败，在 AstrBot 根目录执行：

```powershell
uv pip install --python .venv/Scripts/python.exe -r data/plugins/astrbot_plugin_bilibili_parser/requirements.txt
```

Linux 可将 Python 路径换为 `.venv/bin/python`。也可解压整个插件目录到 `AstrBot/data/plugins/` 后重载插件。

从 0.3.0 升级时保留已有群配置，新建订阅数据库，动态总开关默认关闭。重新导入 ZIP 不携带本机的订阅数据；迁移机器需要另行备份下文的数据目录。

## 动态订阅：QQ + Web

### Web 入口

AstrBot WebUI → 插件管理 → **Bilibili 视频解析、动态与直播订阅** → **Pages / 动态与直播订阅**（页面名 `subscriptions`）。复用 AstrBot 后台登录，不需要另起 Web 服务器。

1. 在“设置”中允许目标 QQ 群，检查 NapCat 已登录且连接到 AstrBot。
2. 在“订阅管理”添加 UP 主 UID 或主页地址，核对昵称，勾选一个或多个群、动态类型和视频开关。
3. 在“设置”开启动态订阅推送，等待列表显示“运行中”。首次成功检查只建立基线，不发送旧动态。
4. “检查”安排一次采集；“测试”明确发送最新的一条匹配动态，卡片标注“测试推送”。两者共用每条订阅 60 秒冷却。

页面包含订阅管理、最近 100 条推送记录、最近 30 条手动任务、运行设置、群过滤和可选 Bilibili Cookie。约每 15 秒更新状态。过期的编辑会提示刷新，防止 QQ 和 Web 互相覆盖。

### QQ 指令

以下用 `/` 表示 AstrBot 指令前缀，实际按你的机器人配置使用。所有指令只操作当前群。

| 指令 | 说明 |
| --- | --- |
| `/bili 帮助` | 查看用法 |
| `/bili 订阅 123456` | 订阅 UID 的全部动态类型 |
| `/bili 订阅 https://space.bilibili.com/123456 视频` | 只订阅视频投稿 |
| `/bili 列表`、`/bili 状态` | 查看本群订阅、最近成功检查和发送状态 |
| `/bili 暂停 123456`、`/bili 恢复 123456` | 暂停或恢复 |
| `/bili 取消 123456` | 取消本群订阅 |
| `/bili 暂停全部`、`/bili 恢复全部` | 操作本群全部订阅 |
| `/bili 设置 123456 类型 视频,图文,文字` | 筛选类型；另支持转发、专栏、其他 |
| `/bili 设置 123456 视频 关` | 关闭这一条订阅的 MP4 发送 |
| `/bili 检查 123456` | 排队检查新动态 |
| `/bili 测试 123456` | 发送最新的一条匹配动态作为测试 |

普通群成员可查看帮助、列表和状态。修改、检查和测试需要本群群主、群管理员或 AstrBot 管理员权限；群管理员角色通过 OneBot 重新查询确认。全局开关、群过滤和 Cookie 通过 Web 设置。

### 检查与发送规则

- 默认每个 UID 约 180 秒检查一次，附带随机错开；相邻 Bilibili 动态请求至少间隔 3 秒。同一 UID 被多个群订阅时合并采集，各群分别筛选。
- 首次订阅、恢复暂停、重新允许群、重新开启总开关，都从新的成功初始化开始，不补发停用期间的内容。
- 动态 ID 去重，旧置顶不重复；每次最多抓 5 页。短暂故障后最多自动补最近 24 小时内容，每群待推送上限 10 条，超出上限和分页缺口会显示状态。
- 视频投稿沿用视频卡片，并按设置附上 MP4；文字和图文使用相同国风背景、独立角色顶栏与磨砂样式，配真实二维码。图文最多展示 9 张图，长正文截取预览，完整内容通过链接查看。
- 同群按队列处理卡片与视频。卡片成功后视频失败，只重试视频。暂时失败最多重试 3 次，间隔 1、5、15 分钟；确定的视频超限、缺少依赖等直接记录失败，可在修复后手动重试。
- 发送超时或进程在发送时退出，会标为“待核对”并阻止本群后续任务。查看群记录后，在 Web 选择“确认已发”或“确认未发并重试”，避免自动重复发送。其他群可以继续。
- 渲染失败时回退文字和链接。视频发送需要 NapCat 可以读取 AstrBot 的本地视频路径。

### Bilibili 接口状态

匿名动态接口可能返回 HTTP 412、403、429 或登录相关错误。Web 会显示实际原因，失败不会推进成功基线；自动采集逐步退避，最长约 1 小时。可以在设置中填入你自己的有效 Bilibili Cookie，原值不会返回页面或 QQ。Cookie 不保证解除网络侧限制，也不会提供给图片 CDN、T2I 服务或视频下载器。

本次开发环境的真实动态列表请求返回 **HTTP 412**；受限处理已验证，使用有效登录状态连续采集真实新动态仍需在部署环境验证。视频元信息接口正常。不要把“已添加订阅”理解为已成功采集，需查看“最近成功检查”。

### 数据与备份

数据位于 `AstrBot/data/plugin_data/astrbot_plugin_bilibili_parser/`：`subscriptions.sqlite3` 保存订阅、去重 ID、发送阶段与审计；`credentials.json` 保存可选 Cookie；`videos/` 保存视频缓存。已结束发送记录、操作日志和动态正文保留约 30 天，动态 ID、订阅基线及未结束任务保留。

备份或迁移时先停用插件，再复制数据目录，避免遗漏 SQLite 的 WAL 事务。数据库由插件自动迁移到版本 3；插件拒绝打开来自未来版本的数据库。Cookie 文件是本机明文私有配置，不要随安装包分发。

## 使用

允许的群中发送 Bilibili 视频链接、`https://b23.tv/...`、BV/av 号，或从 Bilibili 分享到 QQ 的小程序/JSON/XML 卡片。无需 @ 机器人。卡片必须包含 Bilibili 或 b23 的视频地址；只有图片的截图无法识别。

例如：

```text
https://www.bilibili.com/video/BV1GJ411x7h7
https://www.bilibili.com/video/BV1GJ411x7h7?p=2
BV1GJ411x7h7
```

多 P 视频默认下载第 1 P，可用 `?p=2` 选择。单条消息只解析第一个支持的视频。忽略机器人自身消息和私聊。同群同视频默认冷却 60 秒。

## 群过滤与配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `dynamic_enabled` | `false` | 动态订阅推送总开关；不影响原有链接解析 |
| `dynamic_interval` | `180` | 每 UID 轮询间隔，60～86400 秒；请求受限自动退避 |
| `group_filter_mode` | `whitelist` | `whitelist` 仅白名单；`blacklist` 除黑名单外；`all` 全部 QQ 群 |
| `allowed_group_ids` | 空 | 白名单群号，仅 whitelist 模式使用；空名单不响应任何群 |
| `blocked_group_ids` | 空 | 黑名单群号，仅 blacklist 模式使用；空名单允许全部群 |
| `parse_share_cards` | `true` | 识别 QQ 小程序、JSON、XML 分享卡片；关闭后仍解析文本链接 |
| `comment_sort` | `likes` | `likes`：热门候选按点赞数降序取两条；`hot`：按平台热门顺序取两条 |
| `render_card` | `true` | 原生 HTML 渲染卡片；失败自动回退文字和封面 |
| `send_cover_image` | `true` | 回退文字时附上封面图片 |
| `max_video_mb` | `200` | 下载视频的文件大小上限（MB） |
| `send_video` | `true` | 发送视频文件。关闭后只发磨砂卡片和图文，不再下载视频；链接解析和动态订阅同时生效，订阅级 `send_video` 仍可单独控制 |
| `cache_hours` | `2` | 视频缓存保留小时数，在后续解析时清理 |
| `cooldown_seconds` | `60` | 同群同视频的重复解析间隔（秒） |

群号支持英文/中文逗号、空格、换行或分号分隔。升级时保留旧的 `allowed_group_ids`，未设置新模式时仍按白名单处理。

## 卡片和评论

卡片采用随附的竖版国风夜景 `assets/background.png`，等比例覆盖外层背景，按画布比例居中裁切，不拉伸。顶部整栏独立使用 `assets/character.png` 的角色画面，不随外层背景变化；同时保留角色头像、左上角可扫码二维码、标题、作者、封面、六列统计、三个标签、简介、两条评论和粉色圆角页脚。长简介和评论会使卡片向下增高。二维码包含所选分 P 的视频地址。

调用 AstrBot 原生 `html_render()`，使用 AstrBot 已配置的 T2I 服务；未设置自建地址时使用其官方服务，**无需单独提供渲染服务器**。需要能访问该服务；其会接收卡片模板、公开视频资料和图片。45 秒渲染超时后自动回退图文，继续发送视频。模板位于 `templates/video_card.html`，角色头像来源为 `assets/character.png`。

评论请求 Bilibili 热门列表，合并热门候选并按评论 ID 去重；置顶评论不会因置顶而优先。默认从候选中取点赞最高的两条，可改为平台热度顺序。**未登录接口可能只返回少量热门评论，无法保证覆盖全站该视频的全部评论，也不宣称是全量评论的绝对最高赞。** 无评论时显示“暂无评论”，接口失败时显示“评论暂不可用”。不会生成虚构评论。

## 视频发送

默认下载最高 480P 的 H.264/AAC MP4，先发信息卡，再发视频。缓存位于 AstrBot 的 `data/plugin_data/astrbot_plugin_bilibili_parser/videos/`。

AstrBot 与 NapCat 运行在不同机器或容器时，NapCat 必须能读取视频文件的相同绝对路径（共享目录/卷映射）。此版本通过本地文件路径发视频。仅复制插件 ZIP 不会配置跨机器文件共享。

公开视频一般不需要 Bilibili 登录。接口限流、评论关闭、登录限制、会员/付费/地区限制、视频过大或 FFmpeg 缺失时，相关数据或下载可能失败；可用的图文资料仍会发送。Bilibili 站内接口变化时可能需要更新插件或 yt-dlp。

## 直播通知与记录（0.5.0）

在插件 Pages 的「设置」开启**直播检查、通知和记录**，默认每 60 秒检查一次（可设置 30～3600 秒）。直播总开关与动态总开关独立，群白名单/黑名单仍然生效；旧订阅升级后默认不启用直播功能。

在「添加订阅 / 编辑」中选择本群是否接收直播通知、是否记录该主播。只使用直播功能时可以取消所有动态类型。同一主播在多个群中只采集一次，每个群独立决定是否发送；任一有效订阅开启记录便保存该主播的共享场次记录。列表中的「开启 / 关闭直播通知」立即保存并自动应用，不需重启。关闭通知可继续记录；「暂停」同时暂停该条订阅的动态、直播通知和记录需求，其他群订阅不受影响。

群指令（修改需群管理员、群主或机器人管理员权限）：

| 指令 | 作用 |
| --- | --- |
| `bili 直播订阅 UID` | 开启本群该主播的直播通知与记录；已有动态订阅保留原设置 |
| `bili 直播通知 UID 开/关` | 切换本群某个主播的通知 |
| `bili 直播通知 开/关` | 切换本群所有已订阅主播的通知 |
| `bili 直播记录 UID 开/关` | 开关该主播记录需求 |
| `bili 直播记录 UID [YYYY-MM]` | 查询直播月历，默认本月；仅支持近 30 天记录覆盖的月份 |
| `bili 绑定 UID @群成员` | 管理员一次性将本群成员 QQ 号关联到已订阅主播 UID |
| `bili 解绑 @群成员` | 管理员解除本群关联 |
| `bili 直播记录 @群成员 [YYYY-MM]` | 绑定后，普通群成员也可直接查询该主播的月历 |

QQ群的 `@` 消息只含 QQ 号，无法自动得知 Bilibili UID。绑定由管理员设置，只在当前群和机器人账号下生效；绑定前请先用 `bili 直播订阅 UID` 添加该主播。绑定是查询别名，不代表账号所有权已被验证。若未绑定，机器人会给出设置指令；升级运行中的旧版插件后才可使用这些命令。

开播卡片显示标题、分区、封面、开播时间、已播时长和直播间二维码；连续两次成功检查为未直播/轮播后，发送结束时间和总时长。首次订阅时如果已经开播，会发送当前直播通知；进程重启不会重复发送已记录的同场通知。标题和分区变更会保存在记录中。Web 的「直播记录」显示周一至周日的月历，可切换近 30 天窗口覆盖的月份，并导出当前月历 PNG。每个日期格显示当日累计时长和最多两场直播标题、时段，更多场次与完整标题可展开「本月场次详情」查看。颜色由浅到深表示少于 2 小时、2～4 小时、至少 4 小时；「暂无记录」不表示确认未开播。QQ 使用同样的日期与时长数据，通过 AstrBot 原生 HTML 渲染月历，失败时回退文字。

记录是**直播场次元数据，不是视频录像**。开启后开始积累，无法补齐启用前已结束的直播。结束时间以第一次检测下播的时刻估计，真实下播时间位于最后检测到直播与首次检测下播之间；未结束场次仅统计至最后检测。接口失败、停机或暂停可能造成记录缺口，开播时间缺失时标记为首次检测时间。已结束场次保留 30 天并每小时清理，进行中的场次保留到结束；月历仅统计近 30 天窗口内的时长，跨日直播按北京时间零点拆分并归入各日期；跨月场次会在涉及的月份中各计一场，时长不会重复计算。展开的场次详情保留整场起止时间与时长。记录和发送状态保存在原订阅 SQLite 数据库，升级自动迁移，请勿用旧版插件加载已迁移的数据库。
